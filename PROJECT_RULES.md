# Project Rules & Technical Guidelines

## 1. Стек технологий

* **Фронтенд & Бэкенд:** Next.js 15 (App Router). Единый фулстек-фреймворк для обработки UI и API-роутов.

* **Среда выполнения:** Telegram Mini App (клиентский рендеринг внутри окна мессенджера, интеграция через `window.Telegram.WebApp`).

* **Язык:** TypeScript (строгая типизация обязательна).

* **База данных:** SQLite + Prisma ORM (для MVP), с прицелом на легкую миграцию в PostgreSQL/Supabase.

* **ИИ / API:**

  * Генерация и проверка: OpenRouter API (Gemini Flash / Llama 3 8B).

  * Голос: Whisper STT (Groq API).

* **Управление состоянием:** `zustand` для локального стейта (UI, открытие модалок), `@tanstack/react-query` для работы с API бэкенда.

## 2. Дизайн и UI-библиотека

* **Стилизация:** Tailwind CSS v4.

* **Компоненты:** `shadcn/ui` (кастомизированные под новую палитру).

* **Дизайн-код (Мягкие, теплые пастельные тона):**
  Интерфейс должен вызывать чувство уюта, спокойствия и фокусировать на обучении без визуального стресса.

  * **Фон приложения:** `#FDFBF7` (Теплый, мягкий кремово-белый).
  * **Основной акцент (Успех / Прогресс):** `#C7E5C8` (Мягкий пастельный зеленый, фисташковый или шалфей).
  * **Вторичный акцент (Интерактивные элементы / Карточки):** `#E0BBE4` (Теплый пастельный фиолетовый/лавандовый).
  * **Основной текст:** `#4A4453` (Глубокий серо-фиолетовый вместо жесткого черного, чтобы снизить контраст).
  * **Вторичный текст:** `#8A8493` (Приглушенный серо-фиолетовый).
  * **Бордеры и разделители:** `#E8E2D9` (Теплый бежево-серый).
  * **Шрифт:** Без засечек (например, Inter, Nunito или Helvetica) с мягким начертанием (веса 400, 500, 600).

* **Анти-паттерны (ЗАПРЕЩЕНО):** Использовать кислотные цвета, жесткий черный (`#000`), чистый белый (`#FFF`), неоморфизм, тяжелые контрастные тени, красные агрессивные предупреждения (ошибки подсвечивать мягким персиковым или пыльно-розовым), декоративные анимации. Углы должны быть заметно скруглены (xl или 2xl в Tailwind), чтобы интерфейс казался "мягким".

## 3. Соглашения по коду (Coding Conventions)

1. **Модульность:** Разделяй логику на мелкие функции. Алгоритм SM-2 должен лежать в отдельном утилитарном файле (`utils/sm2.ts`) и быть покрыт базовыми комментариями.

2. **Зависимости:** Не добавляй лишних npm-пакетов без явного согласования. Используй встроенные возможности Next.js и браузера там, где это возможно.

3. **Изоляция и Безопасность:**

   * API-ключи (OpenRouter, Telegram Bot Token) никогда не должны попадать в клиентский бандл. Все вызовы ИИ происходят строго через Next.js Route Handlers (бэкенд).

   * Доверяй только `initData` от Telegram, валидируй криптографическую подпись на бэкенде перед тем, как создавать сессию или сохранять прогресс.

4. **JSON от ИИ:** При работе с LLM используй жесткий system prompt, требующий ответа в чистом формате JSON. Обязательно оборачивай парсинг ответа ИИ в блоки `try/catch` с fallback-поведением.

5. **Оптимистичные UI-апдейты:** Для быстрой работы интерфейса (особенно при нажатии кнопок оценки карточек) используй optimistic updates в React Query, чтобы пользователь не ждал ответа от сервера.
